## 第一部分：产品战略层

### 1. 产品定位与愿景

#### 1.1 一句话定位

LLMine Quant 是面向专业量化团队的 **AI-Native 量化投研与交易系统**，通过自然语言与 AI Agent 协作，将策略从想法到回测到模拟盘的周期压缩至分钟级，并在严格的风控、可解释性、审计追踪约束下运行。

#### 1.2 愿景

> 让专业级量化投研能力民主化——任何一个有投资想法的人，都能通过自然语言与 AI Agent 协作，在严格的风控与可解释性约束下，快速验证策略、管理组合、执行交易。

#### 1.3 V1.0.0 边界

**已交付（前端高保真原型）：**
- 11 个核心功能模块的完整可视化界面
- 玻璃态暗黑主题设计系统
- A 股 / Crypto 双市场数据适配
- 全链路 Mock 数据支撑

**V1.0.0 不包含（后端实现）：**
- 真实行情数据接入（当前为 Mock）
- 实盘交易执行（QMT/PTrade 对接）
- WebSocket 实时推送
- 用户认证与 RBAC 权限系统
- LLM 策略代码生成服务

**V1.0.0 产品目标：**
- 验证产品概念与用户体验
- 作为后续后端开发的"视觉契约"（Visual Contract）
- 支持投资人/团队内部的产品演示与需求确认

### 3. 产品原则与设计理念

#### 3.1 War-Room 设计六原则

1. **零文案宣传** — 界面不出现系统介绍、营销文案。每屏都是作战数据，用户打开即进入工作状态。
2. **数据即语言** — 用数字、图表、颜色、动画传达状态，而非文字描述。健康度用圆环，风险用红色脉冲，趋势用 Sparkline。
3. **状态分级** — 全局统一五色状态体系：
   - `green` = 正常/通过/上涨/活跃
   - `yellow` = 注意/观察/待审批/警告
   - `red` = 告警/失败/下跌/拒绝/危险
   - `blue` = 信息/AI/模拟/系统
   - `purple` = 特殊/回测/草稿/研究
4. **一屏可见** — 核心信息无需滚动即可获取。滚动仅用于详情展开或列表浏览。
5. **随处可点** — 每个卡片、每行数据、每个指标都可点击导航或唤起操作。没有"纯展示"区域。
6. **科技质感** — 玻璃态 (`backdrop-filter: blur(24px)`)、微光边框、流畅过渡、脉冲呼吸灯、数字滚动动画。

#### 3.2 安全优先原则

- **AI 无权触达资金** — AI Agent 只能生成提案，不能执行实盘交易
- **Human-in-the-Loop** — 所有实盘交易必须经过人工审批
- **双人审批** — 风控规则放宽、资金划转等敏感操作需双人确认
- **全程审计** — 每个操作（人 or Agent）写入不可篡改日志，带 Trace ID

### 4. 竞品分析与差异化

| 产品 | 优势 | 劣势 | LLMine 差异化 |
|------|------|------|--------------|
| 聚宽 (JoinQuant) | 社区活跃、数据全、实盘支持 | 代码门槛高、AI 能力弱 | Agent 协作 + 自然语言策略生成 |
| BigQuant | AI 策略生成、可视化 | 黑盒严重、可解释性差 | 可解释归因 + 血缘追踪 + 偏差检测 |
| QMT | 极速交易、机构级 | 昂贵、封闭、学习曲线陡 | 开放架构 + 低门槛 + 现代 UI |
| PTrade | 恒生出品、券商支持好 | 策略灵活性差、UI 陈旧 | 灵活策略层 + AI 增强 + 玻璃态设计 |
| RiceQuant | 回测快、社区好 | 实盘受限、A 股外市场弱 | A 股深度适配 + 风控闭环 + 协作评审 |

**核心差异化总结：**
- **自然语言策略研发**：一句话生成可回测策略，降低 80% 门槛
- **可解释性闭环**：每个信号可追溯到原始数据，带完整归因与血缘
- **AI Agent 协作**：研究/策略/回测/风控/执行多 Agent 分工协作
- **机构级风控**：三层风控 + 熔断 + HITL，不是事后分析而是实时拦截

### 5. 术语表

| 术语 | 英文 | 定义 |
|------|------|------|
| Agent | — | 具备特定能力的 AI 智能体（研究/策略/回测/风控/执行/数据/解释/组合） |
| IS / OOS | In-Sample / Out-of-Sample | 样本内回测 / 样本外验证 |
| Walk-forward | — | 滚动窗口回测，避免未来函数与过拟合 |
| 过拟合 | Overfitting | 策略在样本内表现好，样本外失效 |
| HITL | Human-in-the-Loop | 关键环节人工确认，非全自动 |
| Kill Switch | — | 全局熔断开关，一键停止所有交易 |
| VaR | Value at Risk | 风险价值，给定置信水平下的最大预期损失 |
| DAG | Directed Acyclic Graph | 有向无环图，用于数据血缘追踪 |
| Trace ID | — | 贯穿信号生成到执行的全链路追踪 ID |
| EOD | End of Day | 日终数据/策略 |
| OOS Score | — | 样本外一致性评分（0-100） |
| 滑点 | Slippage | 下单价格与实际成交价格的偏差 |
| 复权 | Adjustment | 考虑分红送股后的价格修正 |
| Feature Store | — | 特征存储与版本管理中心 |
| 数据血缘 | Data Lineage | 从原始数据到最终信号的完整追溯链 |

#### 9.2 熔断规则

| 熔断类型 | 触发条件 | 自动动作 | 恢复方式 |
|---------|---------|---------|---------|
| 可恢复熔断 | 行情延迟 > 5min / 策略心跳异常 | 暂停新开仓，允许平仓 | 自动恢复 |
| 不可恢复熔断 | 资金异常 / 重复下单 / 风控服务宕机 | 全部暂停，冻结账户 | 人工审批恢复 |
| 组合熔断 | 组合回撤 > 15% | 减仓至 50% 仓位 | 人工审批恢复 |
| 全市场熔断 | 大盘单日跌幅 > 7% | 清仓或暂停 | 次日自动恢复 |

| **Explain** | 交易信号 / 策略决策 | 归因报告 + 置信度分析 + 可视化 | 因子分解、SHAP、链路追溯、历史匹配 |
| **Portfolio** | 候选策略 + 资金约束 + 风险偏好 | 最优配置方案 + 风险预算分配 | 均值方差、风险平价、BL 模型、再平衡 |

### 32. 性能需求

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 首屏加载 | < 3s | 包含 JS/CSS/字体，Gzip 后 < 500KB |
| 屏幕切换 | < 200ms | 条件渲染，无需路由跳转 |
| ECharts 渲染 | < 500ms | 首次绘制，ResizeObserver 延迟初始化 |
| 搜索响应 | < 100ms | 本地过滤，无需服务端 |
| 并发用户 | 50+ | 前端无状态，瓶颈在浏览器内存 |
| 数据量 | 5 年日线 | 权益曲线约 1200 个数据点，流畅渲染 |

### 33. 可靠性需求

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 系统可用性 | > 99.5% | 前端静态资源 CDN 部署 |
| 数据一致性 | 最终一致 | Mock 数据层保证前后端 schema 一致 |
| 错误处理 | 优雅降级 | ECharts 失败显示占位符，不影响整体 |
| 离线能力 | 基础查看 | Service Worker 缓存静态资源（V1.2+） |

### 34. 合规需求

| 需求 | 说明 | 实现方式 |
|------|------|---------|
| 审计追溯 | 所有操作可追溯到具体 Actor 和时间 | Audit Log 表 + Trace ID |
| 数据隐私 | 敏感数据不落地前端 | 后端脱敏后返回 |
| 权限隔离 | 不同角色看到不同功能和数据 | RBAC + 前端路由守卫（V1.1+） |
| 不可篡改 | 审计日志防篡改 | 数字签名 + 区块链存证（V2.0+） |
