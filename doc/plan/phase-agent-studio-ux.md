# Agent Studio UX — 下一阶段计划

> 日期：2026-05-16  
> 阶段类型：产品 / 交互设计优先  
> 核心目标：把 Agent 模块从“功能完整的工程工作台”提升为“用户能快速理解、稳定配置、低成本排错的产品级工作台”。

---

## 1. 为什么下一阶段先做 UX

Agent Studio MVP 已经具备完整能力，但当前页面仍有几个明显问题：

1. **信息密度高，但层次不够清楚**  
   Agent 编辑、工作流编排、运行调试、发布版本都在同一页面，第一次进入的用户难以判断“我现在该先做什么”。

2. **功能完整，但学习成本偏高**  
   JSON 编辑器、Schema、Mapping、Override 都直接暴露，适合开发者，不够适合策略研究员或业务用户。

3. **画布能用，但还不像成熟编排工具**  
   缺少更自然的节点选择、连线反馈、缩放 / 对齐 / mini-map / 多选等基础体验。

4. **错误能发现，但还不够可行动**  
   当前校验能告诉用户“哪里错了”，但还没有做到“我点一下就知道该去哪里改、怎么改”。

5. **发布和调试已经有了，但心智模型还没建立**  
   草稿、已发布版本、当前运行对象之间的关系需要更清楚的 UI 表达。

下一阶段如果继续直接上 HITL、run persistence，会让产品能力更强，但也会让页面更难懂。  
所以此时先收一轮 UX，是更好的节奏。

---

## 2. 阶段目标

### 2.1 用户目标

让以下三类用户都能顺畅完成任务：

| 用户 | 他们真正要完成的事 |
|---|---|
| 策略研究员 | 选择 / 复制 / 调整一个 Agent，理解输入输出，接入交易链路 |
| 系统管理员 | 配置模型、权限、约束，发布稳定版本 |
| 交易 / 风控负责人 | 看懂链路、识别风险节点、确认哪个版本正在运行 |

### 2.2 产品目标

下一阶段结束时，Agent 模块应达到：

- 用户知道从哪里开始
- 不看文档也能完成一次 Agent 新建
- 不手写大量 JSON 也能完成常见配置
- 工作流连接关系、数据流、异常点一眼能看懂
- 发布前用户知道自己将发布什么
- 调试失败时用户知道下一步该改哪里

## 3. 设计原则

### 3.1 先引导，再暴露复杂度

复杂配置不能删，但不应该一上来全压给用户。  
应采用：

- 默认简洁
- 逐步展开
- 高级项收纳
- 专家模式可达

### 3.2 让“对象关系”可见

用户必须能看清：

- Agent 定义
- 工作流节点实例
- 发布版本
- 当前调试运行

这四者不是一回事，UI 必须帮助用户建立稳定心智模型。

### 3.3 错误反馈要可执行

好的校验不是只显示红字，而是：

- 告诉我错在哪
- 告诉我影响什么
- 给我一个最快修复入口

### 3.4 面向真实工作流，而不是面向字段表

页面组织应围绕用户动作：

1. 创建 Agent
2. 设计输入输出
3. 接入链路
4. 调试
5. 发布

而不是只按数据库字段分组。

---

## 4. 目标信息架构

建议将当前单页重构为三层：

```text
Agent Studio
├── 1. Agent 库
│   ├── Agent 列表
│   ├── 模板 / 分类 / 搜索
│   └── Agent 详情与编辑
├── 2. Workflow Builder
│   ├── 画布
│   ├── 节点 / 边 Inspector
│   ├── 校验中心
│   └── 发布中心
└── 3. Runs
    ├── 调试运行
    ├── 执行历史
    └── 失败回放
```

### 页面级建议

| 区域 | 设计方向 |
|---|---|
| 左侧导航 | 从“单页塞满”改为“Agent / Workflow / Runs”三级工作区 |
| Agent 编辑 | 从 5 步横向 Tab 改为“基础、模型、契约、权限”分组，并支持向导模式 |
| Workflow | 以画布为主，Inspector 为辅，发布 / 校验作为顶层动作 |
| Runs | 从页面底部附属区升级为独立视图，便于调试与回放 |

## 5. 关键交互设计任务

### UX-1：重构 Agent 模块导航与首屏

目标：

- 用户进入后立刻知道三件事：
  1. 我有哪些 Agent
  2. 当前有哪些工作流
  3. 哪些东西待处理 / 有风险

设计任务：

- Agent Studio 首屏信息架构
- 顶部摘要卡：
  - Agent 数量
  - 工作流数量
  - 已发布版本
  - 待修复校验项
- 主导航：
  - Agent
  - Workflow
  - Runs
- 最近编辑 / 最近发布 / 最近失败运行入口

### UX-2：重构 Agent 编辑体验

目标：

- 对新手像表单
- 对专家保留 JSON 能力

设计任务：

- 新建 Agent 向导
- 基础配置与高级配置分层
- 模型配置采用表单控件 + JSON 双模式
- Prompt 编辑器增加：
  - 变量提示
  - 模板预览
  - 常用片段
- Schema 编辑器增加：
  - 可视化字段表
  - JSON 视图切换
  - 必填字段标记
- 约束与工具权限改为结构化卡片，而不是裸 JSON

### UX-3：重构 Workflow Builder

目标：

- 像真正的编排工具，而不是“能拖的静态图”

设计任务：

- 节点 palette
- 拖拽创建节点
- 节点类型 / 状态 / 风险可视化
- hover 预览输入输出
- 更自然的连线交互
- 边上展示关键 mapping 数量 / 是否有效
- 画布能力：
  - 缩放
  - fit view
  - 对齐
  - mini-map
  - 多选
  - 删除确认

### UX-4：把校验做成“修复中心”

目标：

- 从“显示错误”升级为“帮助修复”

设计任务：

- 校验项按严重级别分组
- 每个错误附：
  - 影响说明
  - 跳转到节点 / 边
  - 快速修复建议
- 发布前统一校验页
- 关键错误阻断发布
- 非阻断警告允许带说明发布

### UX-5：重构发布体验

目标：

- 用户清楚知道自己发布了什么

设计任务：

- 发布前摘要：
  - 节点数
  - 边数
  - override 数
  - 关键 Agent
  - 校验结果
- 发布说明输入
- 与上一版本差异摘要
- 草稿 / 已发布 / 当前运行版本视觉区分
- 版本列表支持：
  - 查看
  - 对比
  - 回滚预留

### UX-6：重构运行调试体验

目标：

- 用户能从“运行失败”快速定位到“哪个节点、哪条输入、哪项映射出错”

设计任务：

- Run 页面独立化
- 输入 payload 模板
- 节点时间线
- 当前节点高亮
- 节点级输入 / 输出 diff
- 失败节点定位
- 一键回到画布对应节点
- 运行结果摘要

## 8. 本阶段暂不优先做的事

为了避免设计阶段再次被功能扩张打散，以下内容暂不作为主线：

- LangGraph human-in-the-loop
- workflow run 持久化
- 多人协作审批
- 版本回滚实现
- 复杂权限体系

这些都重要，但应在 Agent Studio 的基础交互体验稳定后再做。

---

## 9. 验收标准

本阶段完成时，应满足：

- [ ] 用户能在 30 秒内说清楚 Agent / Workflow / Run 三者关系
- [ ] 新用户可以在不阅读文档的情况下完成一次 Agent 新建
- [ ] 用户能从画布上直接理解数据流和风险点
- [ ] 校验错误可以被快速定位并修复
- [ ] 发布动作前，用户清楚知道本次发布包含什么
- [ ] 调试失败后，用户能在 3 次点击内定位到问题节点
- [ ] 设计已形成明确实现优先级，而不是停留在概念层
